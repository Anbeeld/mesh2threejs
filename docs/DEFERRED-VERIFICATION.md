# Deferred verification campaign

The implementation and development checks can be completed without claiming that large real references, every host, or visual-review calibration have been exercised. Production-readiness language remains blocked until the following campaign is run from a frozen repository commit and its artifacts are retained.

## Mechanism checks

Verify executable profile validation, phase locking and dependent invalidation, artifact-content hashing, frozen camera identity, object-unit coordinates, derivative-cache keys, transitive candidate auditing, sampled articulation, atomic CLI state updates, resumption, and artifact-derived finalization.

## Protected adversarial fixtures

Each fixture must record the expected failing gate and earliest route/phase:

- physically mirrored tank with correct forward metadata → `orientation.physical`, hull;
- fore/aft, vertical-seat, and lateral turret errors → `turret.placement`, turret;
- incorrect hull length with plausible overall length → `dimensions.hull-length`, hull;
- antenna outlier with correct structural height → robust dimensions pass;
- opposite wheel-size errors with a correct mean, axle-height error, missing role/side/order instance → `running-gear.instances`, running gear;
- two named boxes, discontinuous wrap, wrong lateral/width/ground/upper run, wheel mismatch, or hull intersection → `track.course`, tracks;
- neutral-only controls, missing yaw/elevation/depression/combined motion, stationary hull movement, or fitting left behind → sampled articulation/ownership, fittings-articulation;
- open hull, disconnected major mass, unseated attachment, or implausible penetration → `fabrication.profile`, style-fabrication;
- missing or ambiguous semantics and duplicate parent/child display names → onboarding/registration;
- changed locked hull → mutation refused until explicit hull reopen; dependants invalidated;
- stale source/prepared/profile/measurement/camera/render/material cache identity → cache miss;
- candidate helper or transitive import loads/embeds the reference or dense topology → candidate audit;
- hand-written `passed: true`, changed artifact result, stale config, or contradictory state → finalization rejected.

## Real-reference corpus

Exercise a clean multipart GLB, a fused mesh, transformed hierarchy, normalized/quantized attributes, sparse accessors, supported and unsupported compressed geometry, and a large CAD-like asset. Capture decoder coverage, semantic identity outcomes, lineage, time, peak memory, cache behavior, and actionable onboarding failures.

Use a T-34-85 reconstruction as the flagship dependency flow. Record every workorder and repair group, phase locks/reopens, iterations, metric movement, regressions, deterministic/style/articulation results, visual findings, candidate complexity, reference defects, runtime, memory, and cache hits. Also run a non-tank multipart hard-surface subject to verify that tank laws do not leak into the generic profile.

## Rendering and visual review

Run matched actual Three.js WebGL captures for reference and candidate with frozen renderer revision, color space, tone mapping/exposure, environment/lights, viewport/DPR, background, cameras, and all six passes. Confirm region evidence is unavailable when semantic IDs are invalid rather than fabricated.

Calibrate the external visual-review rubric against blinded human labels, including subtle macro, material, fabrication, articulation, and intentional coarse-style cases. Record disagreements and false passes. A deterministic worker, same-context replay, or reviewer without image access is an `awaiting-visual-review` result.

## Host trials

Run fresh Codex, Claude Code, and OpenCode sessions. Capture skill discovery and routing, selected context, tool permissions, candidate/reference write boundaries, state resumption after a new session, visual-review capability, and finalizer behavior. Configuration files alone are not evidence.

## Upstream and claim audit

Run `mesh2threejs upstream-drift`, inspect relevant changed files without auto-merging, and update the dated source map only when an adaptation changes. Audit README, root/role skills, profile docs, adapters, package scripts, and handoff language against captured behavior.

Production-readiness claims require every protected fixture, the real-reference corpus, flagship and non-tank flows, actual WebGL evidence, calibrated visual review, all three host trials, upstream review, and the final claim audit to pass with retained hashes.
